# クリニック向け セミセルフレジ（自作）

添付の「OWEN」のようなクリニック用セミセルフレジを、**中古の汎用機＋自作ソフト**で構築するプロジェクトです。
高額な月額保守（15,000〜21,000円/月・5年縛り）と高額スポット部品を避け、
**釣銭機は「替えがきく定番中古機」、ソフトは自作（無償保守）** で組みます。

**スコープ：POSは「現金＋自動釣銭機」に専念**します。キャッシュレス（UA-P10NA）とPayPay（静的QR）は
従来どおり**端末単体で独立運用**し、POSは関与しません。理由は、UA-P10NAへの金額自動連携が
端末側のCAFIS Arch「POS連動」契約を要し、一診療所が自力・無料では実現できないため
（→ [`docs/キャッシュレス連携.md`](docs/キャッシュレス連携.md)）。現金会計の自動化にこそ効果（違算金ゼロ・締め時短）があります。

## 構成

```
自動釣銭機(Glory RT-300系/中古)  ─RS-232C─┐
バーコードリーダー(USB-HID)      ─USB────┤   ミニPC 1台
スタッフ側タッチモニタ ×1        ─HDMI+USB┘   └ Node.js バックエンド
（客側ディスプレイは任意・非タッチ可）              └ 画面配信(WebSocket)

  ※キャッシュレスはUA-P10NA単体、PayPayは静的QR(札立て)でPOSの外で運用
```

- **現金会計を自動化**：レセコン領収書の**バーコードで金額読取**（手入力も可）→ 自動釣銭機で入出金・釣銭。
- **スタッフ画面1枚でOK**：現金のみなら患者は支払方法を選ばず、投入額/お釣りは**釣銭機自身の客面表示**が出す。
  客側画面は不要（付ける場合も"表示だけ"でタッチ不要。ソフトは `…/patient` を無料で出せる）。
- **レシートは原則このPOSから出さない**：医療の**領収書はレセコン**が発行。POS印字は既定OFF（現金の預り/釣銭メモを紙で出したい院のみ任意ON）。
- **ハード無しで動く**：釣銭機/プリンタは**シミュレータ同梱**。実機は設定＋ドライバ差し込みで切替。

## 使い方（デモ＝ハード不要）

```bash
npm install        # ws のみ（serialport は実機時のみ）
npm start
```

- スタッフ側：<http://localhost:8080/staff>（現金運用はこれだけでOK）
- 客側（任意）：<http://localhost:8080/patient>

スタッフ画面で領収書バーコード（または金額手入力）を確定すると、**支払方法選択を省略して
即・入金受付**になります。現金投入は**デモ用ボタン**（シミュレータ時のみ表示）でエミュレートできます。
※客側画面を開くと状態が即ミラーされます（現金運用では必須ではありません）。

## 実機への切替

`config.json` を編集：
- `changeMachine.driver` を `"glory-rt"`、`serial.path` を接続ポートに。
- `printer.driver` を `"escpos-network"`（または `"escpos-serial"`）に。
- `npm install serialport @serialport/parser-inter-byte-timeout`

釣銭機の制御プロトコルは **`docs/釣銭機プロトコル.md`** の手順で「後差し込み」します
（上位アプリ・UIは無改修）。

```
config.json                     運用設定（ここだけで実機/シミュレータ切替）
backend/src/
  server.js                     HTTP静的配信 + WebSocketハブ（ミラーの要）
  checkout/CheckoutSession.js   会計ステートマシン
  devices/changeMachine/        釣銭機：抽象I/F + Glory実機骨組み + シミュレータ
  devices/cashless/             決済端末：抽象I/F + 連動実機骨組み + シミュレータ（半連動/金額連動）
  devices/printer/              プリンタ：ESC/POS + シミュレータ + レシート整形（任意・既定OFF）
  receipt/billParser.js         レセコン領収書バーコード→金額パーサ
  util/                         金種計算・ログ
frontend/public/                患者/スタッフ両対応の1画面（role で切替）+ 多言語
```

## 設計上の注意（正直な論点）

- 会計の正確性は医療の信頼に直結。**導入初期は従来レジと二重運用で締め確認**を。
- **静的QRは自動照合ではなく目視確認運用**。取り違え防止のルールを明文化。
- 中古釣銭機は当たり外れあり。整備済み品＋**予備1台**の入替戦略を推奨。
- 釣銭機の**上位手順仕様書はNDA資料**。本ソフトは差し替え式で対応（詳細は該当doc）。
- キャッシュレスの規約・手数料・PCI等は各社契約に従う（本ソフトはカード情報を扱わない）。
