# キャッシュレス金額連動（半連動 → 自動連携）

UA-P10NA でのキャッシュレス決済を、**2段階**で運用できるよう実装しています。

| モード | config | 動作 | 端末との接続 |
|---|---|---|---|
| **半連動 (semi)** | `cashless.mode = "semi"` | スタッフが端末に金額を手打ち→承認後に画面の「端末承認を確認」を押す | 不要（端末は独立） |
| **金額連動 (auto)** | `cashless.mode = "auto"` | 患者/スタッフが「キャッシュレス」を選ぶと**端末へ金額を自動送信**→承認で**自動完了**。手打ち・確認ボタン不要 | 必要（TCP or シリアル） |

まず **semi** で運用を固め、準備ができたら **auto** へ切り替える流れを推奨します。

## 金額連動（auto）のフェーズ

```
BILL_READY ─(キャッシュレス選択)→ CASHLESS_PROCESSING ─(端末が承認)→ PRINTING → COMPLETE
                                        │
                                        ├─(否認)→ CASHLESS_DECLINED ─(再試行)→ CASHLESS_PROCESSING
                                        │                          └─(取消)→ IDLE
                                        └─(取消)→ BILL_READY / IDLE
```

- **クレジットの利用控え（承認番号入り）は UA-P10NA 本体が発行**します。POSからは印字しません（二重発行防止）。
  承認番号・ブランドは画面表示や締めの突合には使えますが、レシート印字には使いません。
- 本ソフトは**カード番号等の機微情報を保持しません**（受け取るのは承認可否と伝票番号・ブランド名のみ）。

## シミュレータでの動作確認（ハード不要）

`config.json`（既定）:
```json
"cashless": {
  "enabled": true, "terminalModel": "UA-P10NA", "mode": "auto",
  "link": { "driver": "simulator", "simulateApprovalMs": 2500 }
}
```
- 「キャッシュレス」を選ぶと `simulateApprovalMs` 後に**自動承認**されます（＝無操作で完了する連動の動き）。
- スタッフ画面の **［デモ］承認 / ［デモ］否認** ボタンで、承認・否認を任意に発生させられます。
- 否認→「再試行」→承認、処理中の「取消」も確認できます。

## 実機（UA-P10NA）への切替

### 正直な注記（釣銭機と同じ考え方）

UA-P10NA の**上位（POS）連携インターフェースの電文仕様**は、決済端末ベンダー／決済会社の
**NDA資料**です。確定した電文を本リポジトリに載せることはできません。そこで本ソフトは
`backend/src/devices/cashless/LinkedCashlessTerminal.js` に「接続」と「電文の送受信の枠」だけを用意し、
実際の電文は **`PROTOCOL` / `_buildRequest()` / `_onData()` に後差し込み**する構造にしています。
上位（会計ロジック・UI）は無改修で実機化できます。

### 切替手順

1. UA-P10NA の連携方式（TCPソケット／シリアル）と電文仕様を、**端末ベンダー／決済会社から入手**。
2. `config.json`:
   ```json
   "cashless": {
     "mode": "auto",
     "link": {
       "driver": "linked-tcp",              // または "linked-serial"
       "network": { "host": "192.168.0.40", "port": 5000 },
       "serial":  { "path": "/dev/ttyUSB2", "baudRate": 9600, "parity": "none" }
     }
   }
   ```
3. `LinkedCashlessTerminal.js` の3点を仕様に合わせて実装：
   - `PROTOCOL.SALE_REQUEST` / `CANCEL_REQUEST` … 売上要求・取消の電文
   - `_buildRequest(amount)` … 金額を電文に載せる（BCD/ASCII等）
   - `_onData(buf)` … 応答電文を解釈し、`approved` / `declined` / `canceled` を emit
4. `npm install serialport`（シリアル連携時）。
5. `DEBUG=1 npm start` で TX/RX を見ながら、少額決済→承認→レシートまでを実機確認。

### emit すべきイベント（シミュレータと同一）

| 事象 | emit |
|---|---|
| 受付開始 | `this.emit('started', { amount })` |
| 承認 | `this.emit('approved', { amount, approvalNo, brand, method })` ※approvalNo等は画面表示・締め突合用。レシート印字はしない |
| 否認 | `this.emit('declined', { reason })` |
| 取消完了 | `this.emit('canceled', {})` |
| 異常 | `this.emit('error', { code, message })` |

これらの名前・引数はシミュレータと完全に同一なので、会計ステートマシンは変更不要です。

## 運用上の注意

- **二重決済の防止**：処理中(CASHLESS_PROCESSING)は次の会計に進めない設計。取消は端末へも取消要求を送る。
- 通信断・タイムアウト時は端末側の実売上と画面表示が食い違う恐れがあるため、**端末のジャーナル（取引履歴）と締めで突合**する運用を。
- 連携仕様が入手できない場合は、当面 **semi（半連動）** で運用しても業務は成立します。
